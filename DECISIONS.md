### 30.09.2026 · Как проверяется работа без облака
- **Решено:**
  1. **База.** Каждый прогон — чистая PostgreSQL 16 (локально и служебный контейнер в CI); схема создаётся
     только миграциями с нуля, та же версия PostgreSQL, что в Yandex Managed PostgreSQL.
  2. **Файлы.** Код хранилища — один, S3-совместимый (как Yandex Object Storage). В CI он проверяется против
     MinIO (S3-совместимое хранилище в контейнере) — загрузка, временные ссылки, удаление; в быстрых проверках —
     вариант «в памяти».
  3. **Внешние сервисы** (СМС/звонок, ЮKassa, YandexGPT/GigaChat, почта) — каждый за своим интерфейсом
     «поставщик», выбор — настройкой. В тестах — поддельные поставщики, которые записывают вызовы и отвечают
     заранее заданным образом (успех, отказ, задержка). Настоящие поставщики подключаются только после облака
     и договоров (решает Дамир).
  4. **Замена «проверки на боевом адресе».** CI собирает тот же контейнер, который потом пойдёт в облако,
     запускает его вместе с базой и MinIO и прогоняет против него Playwright на экране 412×915; скриншоты
     сохраняются к прогону. Задача до облака закрывается по зелёному прогону на PR и отмечается в `TASKS.md`
     как «проверено без облака».
  5. **Долг проверки.** После подключения облака — один общий прогон всех закрытых задач на `stage`;
     только после него отметки «без облака» снимаются. До этого ничего не называется «выпущенным».
  6. **Данные.** Только тестовые, создаются самими тестами, телефоны `+7999000xxxx`, домены `example.ru`/`.test`.
- **Почему:** максимально близко к боевому контуру без затрат и без зарубежных сервисов; ручных действий у Дамира нет.
- **Отвергнуто:** временный зарубежный хостинг для показа (противоречит правилу «данные только в РФ» даже
  для тестов — привычка опасная); стенд на компьютере Дамира (ручная работа, не повторяется в CI);
  проверять только «в памяти» без S3-совместимого хранилища (не ловит ошибки настоящего хранилища).
- **Кто:** Claude (поручено Дамиром 30.09.2026).

### 30.09.2026 · Каркас ядра (задача 1.1): технические решения
- **Решено:**
  1. **Основа:** Node.js 22, модули ESM без сборки и без TypeScript; express 5, `pg`, `@aws-sdk/client-s3`
     (+ `s3-request-presigner` для временных ссылок). Как в наследии — меньше зависимостей и переучивания.
  2. **Доступ «свой/чужой» — одним механизмом.** Все операции описаны в реестре; каждая обязана объявить,
     кто её вызывает: открытая (только с объяснением и из утверждённого списка), «только своё», или предмет
     (заявка/документ) с уровнем «читать/менять» — предмет загружается и проверяется до обработчика. Правила —
     в одном файле `src/access/policy.mjs`. Чужому отвечаем «не найдено» (не раскрываем, что заявка есть).
     Тест сверяет реестр с таблицей проверок: новая операция без теста «чужой не видит» — CI красный.
  3. **Кто что видит (до задач 1.2–1.4):** владелец — читает и меняет; руководитель организации — все заявки
     организации; сотрудник — только свои; диспетчер и администратор — читают все, менять пока не могут.
  4. **Вход:** код 6 цифр, случайный, в базе только хэш; 5 ошибок сжигают код; не больше 10 ошибок и 5 кодов
     на номер в час; новый код не раньше чем через минуту; отключённый пользователь не входит, его сессии гаснут.
     Сессия — в cookie `HttpOnly; SameSite=Strict; Secure`, в базе только хэш токена. Изменяющие запросы — только
     со своих страниц (служебный заголовок). Регистрация по первому входу — без служебных ролей.
  5. **Схема:** SQL-миграции по номерам, каждая в своей транзакции, с контрольной суммой (изменить применённую
     нельзя); запуск отдельной командой, не из интернета. Схема `public` в базе `delo` (владелец — `delo_app`).
     Блокировка на время миграции — на транзакцию (работает через пулер соединений Яндекса).
  6. **База:** без сертификата не подключаемся; параметры SSL из строки подключения не могут отключить проверку.
     Сертификат Яндекса кладётся в образ при сборке.
  7. **Заявка в каркасе — заготовка** (владелец, организация, название) — нужна, чтобы проверки доступа
     и документы работали с первого дня. Поля, статусы и описание модулей — задача 1.3.
  8. **Поддельные поставщики** (СМС, оплата, ИИ, почта) записывают вызовы и отвечают по сценарию
     (успех/отказ/задержка). На prod запрещены настройкой — сервер не стартует. На stage допустимы
     (там только тестовые данные), но файлы на stage/prod — только S3, база — только с сертификатом.
     Автотесты читают вызовы через служебные пути `/__test/...`, которые существуют только при `APP_ENV=test`
     и открываются только по служебному токену.
  9. **MinIO в CI — образ `pgsty/minio`** (сборка того же сервера MinIO): официальные образы MinIO на Docker Hub
     больше не публикуются. Версия закреплена.
  10. **Страницы:** без внешних ресурсов (шрифты системные), без встроенных скриптов, строгая политика
      безопасности содержимого; пользовательский текст — только как текст (тест ищет запрещённые приёмы в `public/`).
- **Почему:** закрыть с первого дня дыры наследия Б-1, Б-2…Б-7, Б-9, Б-11, Б-13…Б-15, Б-20, Б-22 (`AUDIT.md`, разделы 5, 10)
  и проверять всё без облака.
- **Отвергнуто:** TypeScript и сборщик (лишний шаг, пока кода мало); ORM (скрывает запросы, сложнее проверять доступ);
  проверка доступа внутри каждого обработчика (легко забыть — как в наследии); код входа 4 цифры (легче перебрать);
  хранить сессию в `localStorage` (Б-9); MinIO из официального Docker Hub (образа больше нет).
- **Кто:** Claude.
