## Начало и конец сессии
- Начало: прочитать `CHARTER.md`, `STATE.md`, `TASKS.md`, `DECISIONS.md`; продолжать с первой незакрытой задачи.
- Конец (и перед исчерпанием контекста): обновить `STATE.md` — сделано / не проверено / следующий шаг /
  последние коммиты; сказать «время переходить в новый чат».
- Всё, что решает Дамир, — одним списком в `STATE.md` → «Решить Дамиру». Ход работы Дамиру не присылать,
  ручных проверок не давать, объяснять без технических терминов, обращение на «Вы».
- Решения — в `DECISIONS.md` (дата, что, почему, что отвергнуто, кто). Идеи сверх этапа — в `IDEAS.md`.

## Что строим
Одно ядро (учётки и организации, заявки, подбор, документы и подписи, оплата, уведомления, ИИ, API) +
модули-профессии (экспертиза → переводы → юристы → …) + кабинеты (клиент, специалист, организация,
диспетчер, админ) по одному образцу. Новая профессия = перечень услуг + поля заявки + список ИИ-проверок.
Первый продукт — «Дело: Экспертиза» (оценка), Москва и область. БЕРТЕЛ CRM не сливается с ядром;
связь только мостом CRM → Платформа без персональных данных.

## Порядок этапов (менять нельзя)
0 аудит и фундамент → 1 ядро → 2 экспертиза → 2а переводы → 3 юристы → 4 API.
Первая версия узкая; идеи — в `IDEAS.md`.

## Жёсткие правила
- Данные только в РФ (152-ФЗ): Yandex Managed PostgreSQL, Yandex Object Storage, Lockbox.
  Никаких Neon/Netlify Blobs/зарубежных моделей в контуре с персональными данными. Данные базы не
  выгружать через GitHub.
- ИИ — модель как настройка (старт YandexGPT Pro, запасная GigaChat). ИИ ничего не подаёт и не
  отправляет сам; ИИ-проверка — помощь, подпись и ответственность у человека.
- Чужие дела не видны никому: проверка владельца/организации в каждой операции, тест на каждую операцию.
- Ключи и пароли — никогда в репозиторий, память, документы. Спрашивать у Дамира один раз за сессию.
- Изменения — через PR; в `main` сливать только после «да» Дамира. Боевой релиз двигает только Дамир.
  Ничего необратимого (удаление данных, смена схемы без копии, платежи, договоры) без явного «да».
- Тестовые данные помечены (телефоны `+7999000xxxx`).
