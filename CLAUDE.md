## Что строим
Одно ядро (учётки и организации, заявки, подбор, документы и подписи, оплата, уведомления, ИИ, API) +
модули-профессии (экспертиза → переводы → юристы → …) + кабинеты (клиент, специалист, организация,
диспетчер, админ) по одному образцу. Новая профессия = перечень услуг + поля заявки + список ИИ-проверок.
Первый продукт — «Дело: Экспертиза» (оценка), Москва и область. БЕРТЕЛ CRM не сливается с ядром;
связь только мостом CRM → Платформа без персональных данных.

## Порядок этапов (менять нельзя)
0 аудит и фундамент → 1 ядро → 2 экспертиза → 2а переводы → 3 юристы → 4 API.
Первая версия узкая; идеи — в `IDEAS.md`.

## Жёсткие правила
- Данные только в РФ (152-ФЗ): Yandex Managed PostgreSQL, Yandex Object Storage, Lockbox.
  Никаких Neon/Netlify Blobs/зарубежных моделей в контуре с персональными данными. Данные базы не
  выгружать через GitHub.
- ИИ — модель как настройка (старт YandexGPT Pro, запасная GigaChat). ИИ ничего не подаёт и не
  отправляет сам; ИИ-проверка — помощь, подпись и ответственность у человека.
- Чужие дела не видны никому: проверка владельца/организации в каждой операции, тест на каждую операцию.
- Ключи и пароли — никогда в репозиторий, память, документы. Спрашивать у Дамира один раз за сессию.
- Изменения — через PR; в `main` сливать только после «да» Дамира. Исключение: PR, где меняются только
  `STATE.md`, `TASKS.md`, `DECISIONS.md`, Claude сливает сам после зелёного CI (`DECISIONS.md`, 30.09.2026).
  Боевой релиз двигает только Дамир.
  Ничего необратимого (удаление данных, смена схемы без копии, платежи, договоры) без явного «да».
- Тестовые данные помечены (телефоны `+7999000xxxx`).

## Код ядра (каркас — задача 1.1)
- Node.js 22, ESM без сборки; express 5, `pg`, `@aws-sdk/client-s3`. Точка запуска — `src/server.mjs`.
- `src/config.mjs` — настройки из окружения; на prod запрещены поддельные поставщики, база без сертификата,
  служебные тестовые пути (сервер не стартует).
- `src/http/router.mjs` — **реестр операций**: каждая операция объявляет `auth` и `access`
  (`'self'`, `{ resource, param, need }` с уровнем `read`/`write`/`manage` или `{ platform: 'admin' }`);
  без объявления не запускается. Правила «свой/чужой» —
  только в `src/access/policy.mjs`. Новая операция = строка в `tests/server/access.test.mjs`, иначе тест красный.
- Операции: `src/ops/core-ops.mjs` (вход, профиль, документы), `order-ops.mjs` (заявка: перечень услуг, заполнение,
  статусы), `org-ops.mjs` (организации, приглашения), `admin-ops.mjs` (служебные роли), `match-ops.mjs` (специалисты, допуски, подбор),
  `work-ops.mjs` (переписка, проверка результата по правилам модуля), `money-ops.mjs` (цена, оплата при заказе, повтор выплаты и
  возврата, сводка; расчёт 80/20, выплата при «готово», возврат при отмене — `src/money/money.mjs`, вызов из шага статуса), `notify-ops.mjs` (лента уведомлений, настройки СМС;
  реестр видов и событий — `src/notify/registry.mjs`, запись и очередь СМС — `src/notify/notify.mjs`), `ai-ops.mjs` (вход через
  проблему, ассистент, ИИ-проверка результата; подсказки и лимит — `src/ai/ai.mjs`, чтение отчётов PDF/Word и отмеченные места — `src/ai/extract.mjs`, модели — `src/providers/ai.mjs`), `draft-ops.mjs` (черновик заключения от ИИ: версии, правка исполнителем, Word в результат — `src/docs/docx.mjs`; разделы — `draft` в модуле), `inspect-ops.mjs` (дистанционный осмотр: ссылка владельцу без входа — открытые операции `/api/inspect…` по секрету ссылки в заголовке, фото с временем и геометкой; шаги — `inspection` в модуле; страница владельца — `public/osmotr.html`), `onsite-ops.mjs` (экспресс: выезд помощника на объект — назначает исполнитель, помощник видит
  только свой выезд, снимает по шагам осмотра и пишет данные с объекта; описание — `express` в модуле; страница — `public/osmotr.html?visit=…`), `mail-ops.mjs` (почта для заявок в профиле; приём и разбор писем — `src/mail/inbound.mjs`,
  письма в переписку заявки — `src/mail/outbox.mjs`), `bridge-ops.mjs` (мост CRM → Платформа: `auth: 'bridge'`, подпись — `src/bridge/signature.mjs`,
  профили, предложения госзаказа, загрузка — `src/bridge/crm.mjs`; ключ `CRM_BRIDGE_SECRET`, без него мост выключен). Первый администратор —
  `node src/tools/grant-role.mjs <телефон> admin` в контуре; на площадке stage — кнопка `Stage admin (Yandex Cloud)`
  (тестовый номер `+79990009500`, только stage; на prod — отдельно и только с «да» Дамира).
- Модули-профессии — **данными**: `src/modules/<модуль>.mjs` (услуги, поля заявки, ИИ-проверки), формат и проверка —
  `src/modules/index.mjs` (ошибка в описании — сервер не стартует). Новая профессия = новый файл описания + строка
  в `DEFAULT_MODULES`; код ядра не трогать. Меняется только через PR (решение Дамира 30.09.2026).
- Статусы и переходы заявки — таблицей в `src/orders/workflow.mjs`; кто какая сторона (заказчик/диспетчер) —
  `orderSides` в `policy.mjs`. Шаг статуса всегда с `from` (что человек видел) — иначе «уже изменился».
- `migrations/NNN_имя.sql` — схема только миграциями; применённый файл не менять, только новая миграция.
- `src/providers/` — внешние сервисы за интерфейсами (СМС, оплата, почта — поддельные; ИИ — поддельная, YandexGPT, GigaChat; файлы — память или S3).
- `public/` — страницы (вход, кабинет): без внешних ресурсов, без встроенных скриптов, текст только через `textContent`.
- `infra/` — контур РФ (Terraform), перенесён из наследия; workflow `Infra (Yandex Cloud)`.

## Локальный запуск и проверки
```
service postgresql start                  # PostgreSQL 16; база delo_test (TEST_DATABASE_URL)
npm ci
npm test                                   # сервер; с MinIO: S3_TEST_ENDPOINT=http://127.0.0.1:9000 npm test
npm run test:ui                            # телефон 412×915 на локальном стенде, скриншоты — test-results/screens/
```
CI (`.github/workflows/ci.yml`): сервер + MinIO; сборка контейнера → миграции → запуск с базой и MinIO →
Playwright против контейнера. Скриншоты — артефакт `phone-screens` прогона.
